# 번역 도우미 (문서 번역) 메모

`/portal/campteam/translate/` 는 이제 **문서 파일 번역 전용**이다. 짧은 글 번역은 루미 도우미의 「번역」 탭이 맡고,
같은 API(`POST /api/campteam/translate` 의 `text` 방식)를 그대로 쓴다 — 그 계약은 바뀌지 않았다.

## 어떻게 돌아가나

1. 사용자가 파일을 올리면 **브라우저 안에서만** 연다(`public/portal/campteam/doc-translate.js`). 파일 자체는 서버에 올라가지 않는다.
2. 파일 이름·글에서 돈 파일인지 먼저 확인한다(아래 「돈 파일 막기」). 걸리면 한 글자도 보내지 않는다.
3. 글 조각(문단·표 칸·슬라이드 줄·엑셀 글자 칸)을 뽑아 언어를 판단한다(한글 글자 수 ≥ 영문 글자 수 → 한국어 → 영어, 아니면 영어 → 한국어). 사용자가 「방향 바꾸기」로 뒤집을 수 있다.
4. 같은 글은 한 번만 보내고, 이미 목표 언어인 칸(숫자·이름·영어뿐인 칸 등)은 보내지 않는다. 긴 글(2,500자 초과)은 문장 끝에서 나눈다.
5. 조각을 묶음(chunk: 최대 40개 · 4,500자)으로 서버 `POST /api/campteam/translate` `{ action:'doc', units, to, kind, name }` 에 보낸다. 화면은 2개씩 동시에 보낸다.
6. 서버는 용어집(`glossary`: 그대로 두기·고정 번역)을 넣어 모델에게 「같은 길이의 JSON 배열로만 답하라」고 시키고, 길이·모양을 검사한다. 틀리면 반으로 쪼개 다시 시킨다(한 요청에 모델 호출 최대 6번). 끝내 못 한 조각은 원문을 그대로 두고 `kept` 번호로 알린다.
7. 모든 묶음이 끝나면 브라우저가 새 파일을 만들어 `<원본이름>_en.docx`(또는 `_ko`, pptx·xlsx 는 같은 확장자)로 내려받게 한다.

문서 글은 어디에도 저장하지 않는다. 서버 기록(`audit_log`, action `translate_doc_chunk`)에는 「방향 · 조각 수 · 글자 수」만 남는다.

## 한도

| 항목 | 값 | 바꾸는 곳 |
| --- | --- | --- |
| 파일 크기 | 15MB | `doc-translate.js` 의 `MAX_FILE` |
| 번역할 글자 수 | 60,000자 | `doc-translate.js` 의 `MAX_CHARS` |
| 한 번에 서버로 보내는 양 | 40개 · 6,000자 | 서버 `functions/lib/campteamTranslateDoc.js` 의 `MAX_UNITS`/`MAX_CHARS` (브라우저는 `MAX_UNITS`·`CHUNK_CHARS=4500` 로 더 작게 보낸다) |
| 사람마다 1분 | 30번 | Cloudflare 변수 `CAMPTEAM_DOC_PER_MIN` |
| 사람마다 하루 | 400번 | Cloudflare 변수 `CAMPTEAM_DOC_DAILY` |

- 이 한도는 루미·글 번역의 공유 AI 한도(`aiLimit`, `campteamLimits.js`)와 **따로** 센다. `AI_ACTIONS` 에 `translate_doc_chunk` 를 넣지 않았다.
- 60,000자 문서는 약 14~20번의 요청이다. 하루 400번이면 큰 문서 20개 안팎. 늘리려면 위 변수만 바꾸면 된다(코드 수정 불필요). 글자 수 한도를 늘릴 때는 브라우저 메모리와 번역 시간(묶음당 몇 초)을 같이 생각한다.
- 모델 호출은 한 요청에 최대 6번이지만 한도에는 「요청 1번」으로 센다.

## 서식이 지켜지는 것 / 안 지켜지는 것

방식: 문서 안 XML 의 **글 칸만** 바꾸고, 나머지 파일(그림·스타일·표 모양·수식·설정)은 **압축된 바이트 그대로 복사**해서 다시 zip 으로 묶는다(시험이 바이트 동일을 확인한다).

**Word(.docx)** — 본문·머리말·꼬리말·각주·미주의 `w:t` 글. 문단 안에서 줄바꿈(`w:br`)·탭·필드(`fldChar`/`instrText`)·그림/도형(`w:drawing`, `w:pict`) 같은 「끊는 표시」로 나뉜 구간마다 한 조각으로 번역한다. 글상자 안의 문단은 따로 센다.
**PowerPoint(.pptx)** — 슬라이드·발표자 노트·스마트아트의 `a:t` 글. 슬라이드 번호·날짜 같은 필드(`a:fld`)는 건드리지 않는다. 슬라이드 레이아웃·마스터의 안내 문구(「제목을 입력하세요」)는 번역하지 않는다. 차트 안의 글(축 이름·범례)은 번역하지 않는다.
**Excel(.xlsx)** — 공유 문자열(글자 칸)과 칸 안 글(`inlineStr`)만. **수식·숫자·날짜·서식·시트 이름은 한 글자도 바꾸지 않는다**(수식이 시트 이름이나 글자로 값을 찾는 경우가 있어서). 칸 메모·도형·차트 안의 글은 번역하지 않는다. 글자로 값을 찾는 표(VLOOKUP 등)는 번역 뒤 확인해야 한다. 일본어 후리가나(`rPh`)는 틀려지므로 지운다.

**한 문단에 글 칸(run)이 여러 개일 때의 절충**: 한 문장을 칸별로 쪼개 번역하면 어순이 바뀌어 엉망이 되므로, 구간 전체를 한 번에 번역해서 **첫 번째 글 칸에 번역문 전체를 넣고 나머지 칸은 비운다**. 그래서 문단 안에서 굵게·기울임·색이 섞여 있었다면 번역문은 첫 칸의 서식 하나로 통일된다. 문단 모양(정렬·들여쓰기·목록)은 그대로다. 링크 글자는 칸이 첫 칸에 합쳐지면 링크가 풀릴 수 있다(링크 칸이 첫 칸이 아닐 때).
앞뒤 공백은 원래 것을 유지한다.

**PDF** — 글만 뽑아서(가벼운 자체 읽기: 글 위치로 줄을 나누고 줄 간격이 넓으면 문단을 나눔, 글꼴의 ToUnicode 표로 한글을 되돌림) **새 Word 파일(.docx)** 로 만든다. PDF 의 모양·표·그림은 유지되지 않으며 화면에서 시작 전에 알린다. 암호 PDF·스캔 PDF(글이 없음)는 읽을 수 없다고 안내한다. ToUnicode 표가 없는 한글 글꼴의 글자는 빠질 수 있다(화면이 알린다). 2단 편집·표가 있는 PDF 는 문단 순서가 어긋날 수 있다.

**그 밖**: 사진/그림 → 정중히 거절. `.doc .ppt .xls .hwp` 등 옛 형식 → 새 형식으로 저장해서 올리라고 안내. 구글 문서/슬라이드/시트(`.gdoc` 등 바로가기) → 「파일 → 다운로드」로 docx/pptx/xlsx 받아서 올리라고 안내.

## 돈 파일 막기 (서버·브라우저 같은 규칙)

- 파일 이름에 `장부·예산·결산·영수증·정산·회계·입출금·지출·청구서·세금계산서·급여·월급·통장·ledger·budget·expense·invoice·receipt·accounting·payroll` → 거절.
- 글에서: 돈 낱말(위 + 잔액·입금·출금·balance sheet 등)이 서로 다른 종류로 2개 이상, 또는 합쳐서 4번 이상, 또는 1번 이상 + 금액 표기 5개 이상 → 거절. 금액 표기가 8개 이상이고 낱말 대비 20% 이상이어도 거절.
- 브라우저는 이름과 추출한 글 전체를 먼저 보고, 서버는 요청마다(이름·그 묶음의 글) 다시 본다. 두 곳의 규칙 문자열은 `doc-translate.js` 와 `functions/lib/campteamTranslateDoc.js` 에 똑같이 있고, 시험(`campteam-doc-translate.test.mjs`)이 같은지 확인한다 — **한 곳을 고치면 다른 곳도 같이 고쳐야 한다.**
- 참가비 안내처럼 금액이 한두 번 나오는 일반 공지는 통과한다. 지나치게 막히면 위 낱말 목록·임계값을 조정한다.
- 숫자만 있는 엑셀 장부는 글(헤더)만 보이므로 파일 이름·헤더 낱말에 의존한다. 이름이 평범하고 헤더도 평범한 돈 파일은 못 걸러낸다 — 사용자가 올리지 않는 것이 최종 방어선이다.
